## 완료된 것

- 문서 업로드와 문단 분할 (코드 블록 보존)
- 번역 흐름: 비동기 처리, 상태 조회, 실패한 문단만 재시도
- 용어집을 번역에 적용
- 문단 번역문 직접 수정 `PATCH /api/segments/{id}` (PR #20): 실패 문단을 고치면 문서도 DONE이 됨
- 요약: 길이 선택, 번역이 끝난 문서만 요약 가능
- 결과 다운로드: 요약본 또는 번역 전문, md / txt / docx 형식 선택
- Ollama 연동: 번역기와 요약기 구현 (`llm.provider=ollama`일 때 활성화)
- 자동 테스트: 가짜 번역기·요약기와 가짜 Ollama 서버로 흐름 검증

## 실제 모델 확인 (2026-11-16)

qwen2.5:3b (Ollama, CPU 전용 PC)로 앱에서 업로드 → 번역 → 요약(SHORT) → docx 다운로드까지 동작했고, 한글이 정상 표시됐습니다.

긴 문서 테스트 (문단 10개, 코드 블록 포함):

| 항목 | 결과 |
| --- | --- |
| 속도 | 35.7초, 이후 56.1초 (문단당 약 4~6초). 구조 변경 불필요 |
| 코드 블록 | 식별자가 번역되는 문제 → 원문 유지로 수정 (PR #10, 머지) |
| 제목의 `#` | 사라지는 문제 → 유지하도록 수정 (PR #10, 머지) |
| 용어집 | boilerplate code → 보일러플레이트 코드, dirty checking → 더티 체킹, repository → 리포지토리로 적용 확인 |
| 문장 끝 `합니다` 누출, 짧은 제목에서 내용 지어내기 | 프롬프트 수정, 관련 용어만 전달, 과장 출력 방지 (PR #11, 테스트 대기) |
| 의미 왜곡 (예: 첫 문장) | 3B 모델 한계로 보임. 7b 비교 필요 |

아직 미확인인 것: 더 긴 문서의 속도, 7b로 만든 요약의 품질.

## 3b와 7b 비교 (2026-11-17)

같은 문서(문단 10개) 기준이며, 문서 1개·소수 실행이라 일반화할 수 없습니다.

| 항목 | 3b | 7b |
| --- | --- | --- |
| 소요 시간 | 35~56초 | 약 91~107초 |
| 의미 오류 | 어순 뒤틀림, 문장 구조 깨짐 있음 ("주의하십시오 지연 로딩입니다.") | 대부분 정상 |
| 용어 일관성 | 메소드/메서드 혼용 | "메서드"로 통일 |
| 문제 | 의미 왜곡 | 다른 언어 문자(러시아어) 혼입, 일부 문단 반복 실패 |

결정: 로컬 프로필 기본 모델을 qwen2.5:7b로 변경했습니다 (PR #14). 속도 손해는 비동기 처리와 진행도 조회 구조로 감수합니다. 100문단 약 17분은 문단당 약 10초에서 추정한 값입니다.

7b 대응:
- 원문에 없는 키릴 문자·가나·한자가 결과에 섞이면 재시도 후 실패 처리 (PR #14)
- 재시도 시 "한글로만 답할 것" 지시를 덧붙임 (PR #15)
- `fetch join`은 용어집에 "페치 조인"으로 등록하면 적용됨을 확인

7번 문단(`For read-only operations, you should mark ...`)이 3회 연속 FAILED였고, Ollama에 직접 호출해서 원인을 확인했습니다. 7b가 `operations`를 한국어 문장 안에서 러시아어(`операциях`)로 번역하는 모델 습관입니다 (앱 버그 아님).

- 효과 없던 방법 (직접 호출 시험): 강화 지시, temperature 0.8, 문장 단위 번역, 섞인 문장 수정 요청
- 효과 있던 방법: 용어집 힌트 `operations => 작업` (직접 호출 2회 모두 정상). 앱에서 재시도하여 7번 문단 DONE 확인
- 한계: 이 문서에서 막은 것일 뿐, 다른 문서에서 다른 단어가 샐 수 있음. 대응으로 기본 용어집 내장과 문단 수동 수정(PATCH) 기능이 필요함

7b 요약 (SHORT): 35.5초, 2문장, 다른 언어 문자 없음. 일부 문장이 원문 취지와 약간 다름 (문서 1개, 1회 기준).

## 7b 안정성 시험 (2026-11-23)

테스트 문서 3개(문단 5~7개), 기본 용어집 내장 + 출력 길이 제한(PR #30) 적용 상태에서 번역했습니다. 문서 3개·소수 실행 기준이라 일반화할 수 없습니다.

| 문서 | 결과 |
| --- | --- |
| 01 | 1회에 완료 (81초, 실패 0, 다른 언어 문자 0) |
| 02 | 1회차 문단 1개 실패 → `/retry` 1회로 완료 |
| 03 | 4번 문단이 `/retry` 3회 연속 실패. `PATCH`로 수동 번역해 완료 |

확인된 것:
- **300초 멈춤은 사라짐.** 끝나지 않는 출력은 길이 제한에 걸려 1~2분 안에 실패로 처리됨 (PR #30). 이전 멈춤의 원인은 7b가 중국어를 섞어 반복 출력하는 것이었고, 용어집 때문이 아님.
- **일부 문단은 재시도로 안 풀림.** 문서 3의 4번 문단(`Run the application inside a container ... pushes the image to a registry.`)이 그런 경우. 실패 사유는 앱 로그에만 남아 있어 아직 확정하지 못함.
- **가드에 안 걸리는 품질 문제가 `DONE`으로 남음:** 영어 단어가 그대로 남음("개발과-production 환경"), 오역("매우 빠르게 롤백할 수 있는 방법은 ..."). 오역은 자동으로 잡을 수 없어 사용자가 수동 수정해야 함.

대응:
- 실패 문단: `/retry`, 안 되면 `PATCH`로 수동 번역 (수정하면 문서가 DONE이 됨, 확인)
- 시도 중: 여러 문장 문단을 문장별로 나눠 번역하는 방식 (`feature/sentence-split`, 효과 검증 전)

## 모델 비교: EXAONE 3.5 7.8B (2026-11-25)

같은 테스트 문서 3개를 모델만 바꿔 번역했습니다 (`--llm.model=exaone3.5:7.8b`). 문서 3개·1회 시험이라 일반화할 수 없습니다.

| 문서 | qwen2.5:7b (PR #30) | qwen2.5:7b (문장 분할) | EXAONE 3.5 7.8B |
| --- | --- | --- | --- |
| 01 | 81초, 실패 0 | 87초, 실패 0 | 76초, 실패 0 |
| 02 | 실패 1 | 실패 2 | 46초, 실패 0 |
| 03 | 실패 1 (4번 문단 반복 실패) | 실패 1 (같은 문단) | 46초, 실패 0 |

- 문장 단위 분할(`feature/sentence-split`)은 qwen의 실패를 줄이지 못해 머지하지 않음
- EXAONE에서 외국어 혼입 0, 모든 문단 DONE. 속도도 qwen과 비슷하거나 빠름
- 남은 품질 문제: 제목에 `#`이 중복됨("# ## 제목", 수정함), "propagation"이 "확산"으로 번역됨, "메소드/메서드" 혼용, "인터리빙" 같은 외래어 그대로, 어미가 "~하십시오/~하세요/~합니다"로 섞임. 일부는 기본 용어집에 추가해 대응
- 미확인: 시험 중 `ollama ps`로 모델 적용을 직접 확인하지 못함(시험 후에 확인해서 비어 있었음), 반복 시험, EXAONE 라이선스(비상업 연구용으로 알고 있음, 서비스 사용 전 확인 필요)

## 남은 것

- 로그인 (F1): 이메일 로그인(JWT)은 PR #34 테스트 대기. 이어서 소셜 로그인(구글·카카오 팝업): 앱 등록 후 `/api/auth/google`, `/api/auth/kakao` 추가
- 7b 안정성: 모델을 EXAONE으로 바꿔 해결했고 문장 분할은 효과가 없어 버림. 남은 것은 EXAONE 반복 시험과 라이선스 확인. 영어 단어 잔존·오역은 자동 검사가 어려워 수동 수정(PATCH)으로 대응
- 기본 용어집 효과 확인: 위 시험에서는 `operations` 누출만 확인됨, 나머지 용어의 효과는 미확인
- 용어 후보 추천 (F9), 단어장 연동 (F10)

## 결정 사항 (2026-11-25)

- 인증은 JWT (김대희). 로그인 방식은 이메일에 더해 구글·카카오 소셜 로그인을 팝업으로 붙이기로 함 (성헌)
- 입력 파일은 txt, md (최대 5MB). 프론트가 PDF 입력 화면을 백엔드에 맞춰 고치기로 함. 출력은 md, txt, docx, pdf
- 프론트의 "문단 길이"는 백엔드의 요약 길이(SHORT/MEDIUM/LONG)에 해당. 문구는 김대희가 정해서 알려 주기로 함
- 번역 모델은 로컬 EXAONE 3.5 7.8B (PR #33)

## 프론트엔드 참고 (김대희)

- API 명세: `docs/API.md` (초안, 2026-11-19 `main`에 머지). 이상한 곳이 있으면 알려 주세요
- CORS: `/api/**`에 localhost:3000, localhost:5173 허용 (PR #17). 다른 주소는 `app.cors.allowed-origins` 설정
  - 실제 서버 확인 (2026-11-17): localhost:5173 사전 요청은 200과 허용 헤더, 허용되지 않은 출처는 403
- 현재는 로그인 없이 호출 가능합니다 (임시 회원으로 동작).
- 주요 API

| 동작 | 요청 |
| --- | --- |
| 업로드 | `POST /api/documents` (multipart, `file`, 선택 `title`) |
| 번역 시작 | `POST /api/documents/{id}/translate` (202, 상태는 `GET /api/documents/{id}`로 폴링) |
| 실패 문단 재시도 | `POST /api/documents/{id}/retry` |
| 문단 목록 | `GET /api/documents/{id}/segments` |
| 요약 시작 | `POST /api/documents/{id}/summarize` (`{"length":"SHORT"}`) |
| 요약 조회 | `GET /api/documents/{id}/summary` |
| 결과 다운로드 | `GET /api/documents/{id}/result?type=full\|summary&format=md\|txt\|docx` |
| 용어집 | `/api/terms` (CRUD) |

- 오류 응답은 `{ "code": "...", "message": "..." }` 형식입니다.
